# Title
Programming languages and how I choose them (C++ ↔ Python ↔ JS/TS)

# Category
experience

# Problem
Modern AI and data systems often require combining performance-critical components with rapid iteration and product delivery. Choosing the wrong language can create long-term maintenance or performance problems, especially in systems with heavy data processing.

# My role
I have production experience in C/C++, Python, SQL, and Java, and I also build modern web UIs using React/TypeScript in recent AI products. I still write production code and prototypes, particularly when exploring new architectures or proving feasibility.

# What I built
In performance-oriented contexts (e.g., database engines), I use C++ to control memory, execution plans, and low-level performance trade-offs. For AI services, orchestration, and pipelines, I use Python (FastAPI, ML frameworks, agent frameworks) to accelerate iteration while keeping code reproducible and testable. For product UX, I use React/TypeScript to ship usable interfaces rather than demos.

# Scale and impact
The impact is practical versatility: I can go deep in systems internals when needed and also deliver end-to-end features spanning backend, data, and UI. This breadth supports leadership roles where understanding constraints across the stack is critical.

# Tech stack
C/C++ for engine internals; Python for AI services (FastAPI, Pydantic, SQLAlchemy, ML tooling); SQL for data modeling; JS/TS for React frontends; Docker/Compose and Nginx for deployment; common test frameworks across stacks.

# Key decisions and trade-offs
The main trade-off is speed of iteration vs control of performance and resource usage. I aim to keep interfaces stable so components can be replaced if requirements change, and I avoid premature optimization unless scale or latency demands it.
